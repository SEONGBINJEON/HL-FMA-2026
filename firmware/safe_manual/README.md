# 수동 제어 BENCH 펌웨어

이 스케치는 **주행할 수 없는 통신·정지 논리 시험용**이다. `ACTUATION_ENABLED=false`를 정적 검사로 고정했고 `loop()`에서 세 PWM에 항상0, 세 BRK에 항상HIGH만 적용한다. PC의 요청 방향과 실제 출력 필드를 구분한다. 실제 출력 필드는 명령 계산값이며 핀 전압 측정 결과가 아니다.

- [공통 통신 규격](../../docs/manual_protocol_v1.md): 명시적 중립→ARM→새 deadman 입력, MCU 발행 요청150ms 기한,50ms 상태 송신.
- 기존 한 글자 F/B/L/R 명령은 지원하지 않는다. 의미 없는 바이트·잘못된 CRC·만료·중복 응답은 정지하고 새 중립/ARM을 요구한다.
- 조향은 ARM 세션의 첫 비영점 요청부터200ms를 한 번만 센다. 반복 요청이나 중립 요청으로 기한이 연장되지 않는다. BENCH에서도 이 논리는 검사한다.
- 사용자가 보고한 E-stop의 눌림/해제 동작이 이전 설명과 다르므로 확인된 E-stop 입력이 없다. `INTERLOCK_PIN=-1`이며 입력을 추측해 읽지 않는다. 모터 전원 복원 시 재출발 방지의 물리 검증도 아직 없다.
- 조향 중앙·범위·ADC 변화 방향과 엔코더 거리 환산은 설정하지 않았다. 원시 ADC와 모듈러32비트 엔코더 카운트만 보고한다. 검사 코드의 ADC100/900은 가상 입력이며 실제 보정값이 아니다.

## EEPROM

바이트0~11을 `uint32 magic=0x484C4D31`, `uint32 counter`, `uint32 ~counter`로 예약한다(모두 little endian). 부팅 때만 증가·기록·전체 재읽기 비교한다. 예약영역 전체가FF일 때만 최초 초기화를 허용한다. 손상·0카운터·카운터 오버플로·쓰기 검증 실패는 출력 잠금/무효 boot_id 상태로 남으며 자동 복구하지 않는다. 펌웨어를 실제 올리기 전에 기존 EEPROM 원본을 보존해야 한다. 이 구현 작업에서는 보드에 접근하지 않았다.

## 코드와 검사

`control_core.h/.cpp`는 하드웨어 없는 실제 상태기계와 프레임 파서다. `.ino`는 고정된 모터 정지 출력, 원시 센서 읽기, EEPROM, 유한 수신/비차단 송신을 담당한다. AVR watchdog은 아직 추가하지 않았다. `tests/run_manual_core_tests.sh`로 AddressSanitizer/UndefinedBehaviorSanitizer를 켠 C++ 코어 검사를 실행한다. `--vectors`를 붙이면 Python PC와 비교할 바이너리 프레임 벡터를 출력한다.

컴파일 성공과 모의 검사 통과는 전기적 정지나 차량 주행 검증을 대신하지 않는다. 특히 리셋/부트로더 구간의 핀 상태는 이 스케치만으로 보장하지 않는다. 실제 보드 시험은 차량 배터리·모터 구동 전원이 꺼진 조건을 확인한 뒤 진행해야 한다.

## 수신 중 비동기 정지 경계 수정

조향/통신 만료가 유효 프레임의 수신 중간에 발생하면, 제어 상태는 즉시 정지·폐기하고 이미 시작한 프레임은 수락할 수 없는 프레임으로 끝까지 해석한다. 남은 바이트를 새 잡음으로 오해하던 경로를 수정한 것이다. 원래 부분 프레임30ms 제한은 유지하며, 이 프레임의 CONTROL/ARM은 새 명령 기한이나 중립 확인을 부여할 수 없다. 유효 DISARM은 계속 처리한다.

별개의 잘못된 프레임이나 늦은 응답이 이후 도착하면 새 정지 사유가 보고될 수 있다. 정지 사유를 영구 고정하지 않으므로, 타이머를 검증할 때는 불필요한 추가 송신으로 관측 사유를 바꾸지 않도록 시험을 구성한다.

기존 `build_output/`과 `build_provenance.json`은 첫 버전의 기록이며 보존한다. 수신 경계 수정 빌드는 `build_output_rx_abort/`, 근거는 `build_provenance_rx_abort.json`에 둔다. 실제 보드 상태는 프로젝트 `docs/STATUS.md`를 따른다.
