# 협업 규칙 (꼭 읽기)

혼자 개발이 아니라 셋이 함께 만든다. 아래 규칙만 지키면 충돌 없이 붙는다.

## 1. 브랜치

- `main`: 항상 동작하는 버전. 여기에 직접 push 금지.
- 각자 작업 브랜치에서 작업:
  - 하이레벨(인지): `feat/perception`
  - 하이레벨(측위): `feat/localization`
  - 하이레벨(판단): `feat/planning`
  - 로우레벨: `feat/arduino`
- 기능 완성되면 Pull Request(PR)로 `main`에 합침. 총괄이 확인 후 merge.

## 2. 하루 작업 흐름

```
git pull origin main          # 시작 전 최신 받기
git checkout feat/내브랜치      # 내 브랜치로
# ... 작업 ...
git add .
git commit -m "무엇을 했는지 한 줄"
git push origin feat/내브랜치
# GitHub에서 Pull Request 생성 → 총괄에게 알림
```

## 3. 커밋 메시지

- 한 줄로 "무엇을 했는지" 명확히. 예: `신호등 red/green 검출 추가`
- 한 커밋에 한 가지 일만.

## 4. 절대 규칙

- **`docs/interface.md`의 토픽·단위는 마음대로 바꾸지 않는다.**
  바꿔야 하면 총괄에게 먼저 말하고 문서부터 고친다.
- 남의 폴더 코드는 함부로 수정하지 않는다. 필요하면 담당자와 협의.
- 막히면 혼자 오래 붙잡지 말고 회의/채팅으로 공유.

## 5. 소통

- 주 2회 정기 회의: "내가 바꾼 것 / 막힌 것" 공유.
- 인터페이스 바꿀 땐 반드시 사전 공지. (협업 사고 90%가 여기서 남)
