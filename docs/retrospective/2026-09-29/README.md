## 준비 과정에서 확보한 것

1. 센서 수신·보정 기록, 실측 조향 보정, Arduino 목표각 제어와 시리얼 통신.
2. 직접 기록한 약111.8m 경로의 연속 GPS 추종과 HYPER 경로의 현장 적용.
3. 전진 GPS로 출발 방향을 얻는 절차, 적응형 lookahead와 구간 진입, 경사로 정지·버티기.
4. 기존 HYPER 모델을 이용한 신호 평가, OAK 라이브 입력, 라이다 반전 장착의 소비 경로 보정.
5. 미션 연결, 주차 미진입 대안 및 일부 선택 경로 시도, 종점 분기, 제한된 S 충돌 복구.
6. L 자동 준비·명시적 키2 출발, 원시 로그·소스 해시·검사 기록과 버전 보존.

## 검토 과정에서 드러난 문제

- 단품 검사와 정지 READY 확인을 경기 전체 운행 안정성으로 확대해서 설명하면 안 됐다.
- 통신 시작 동기화/부분 프레임 처리, 준비 상태 이유 표시, 종료 후 복구가 경기 직전까지 바뀌었다.
- 정지 중 관측 변화를 복구 잠금으로 전환하는 처리와 hillhold·엔코더·GNSS의 상호작용을 실제 조건으로 충분히 확인하지 못했다.
- 신호 판단 이력이 덮어쓰는 파일에만 남아 당시 재출발 불가 원인을 완전히 재구성하기 어렵다.
- 정지 원인, 미션 상태, 마지막 유효 위치, 잠금 설정·해제 조건을 묶어서 검사하는 검증이 필요했다.
- 후반부 코스·전체 무개입 완주·선택 주차 성공은 모의 결과와 실차 결과를 분리해 설명해야 한다.

원시 자료와 실패 로그는 삭제하지 않았다. GitHub에는 설명 가능한 코드·문서·선별 증거를 올리고, 대용량 원시 자료와 인증정보를 별도 관리하는 방향으로 준비한다.
