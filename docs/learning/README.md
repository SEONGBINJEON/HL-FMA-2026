# 이 프로젝트를 내 지식으로 만드는 학습 순서

목표는 코드의 모든 줄을 외우는 것이 아니라 **센서 입력 하나가 왜 특정 조향·구동·정지 명령으로 이어졌는지 설명하고, 로그로 확인하는 것**이다. 대회 결과와 구현 범위를 먼저 읽고 다음 순서로 진행한다. 차량 없이 시작할 수 있다.

| 순서 | 읽고 할 일 | 스스로 만들어 볼 결과 |
|---|---|---|
| 1. 결과와 전체 흐름 | [회고](../retrospective/2026-09-29/README.md), [시스템 해설](SYSTEM_WALKTHROUGH.md) | 센서→판단→명령→보드→로그를 종이 한 장에 그리기 |
| 2. Python 읽기 | `dataclass`, 함수 입력/반환, 예외, 모듈 import, `Path`, JSON, `unittest` | `Gate` 한 개와 `Mission` 한 개의 상태를 말로 설명하기 |
| 3. 위치와 경로 추종 | [코드 읽기 지도](CODE_READING_GUIDE.md)의 1~3번 | 위치·heading·lookahead·조향각의 관계를 손으로 계산하기 |
| 4. 조향과 통신 | 같은 문서의 4번, `docs/manual_protocol_v1.md` | 목표각과 ADC, 요청과 응답, ACK와 실제 정지의 차이 설명하기 |
| 5. 미션·인지 | 같은 문서의 5~6번 | 빨강→정지→초록→재개에 필요한 조건을 표로 만들기 |
| 6. 실패 재현 | [오프라인 실습](LABS.md), [첫 신호 분석](../retrospective/2026-09-29/LIGHT1_FAILURE.md) | 입력 한 가지를 바꿔 재개 여부가 달라지는 이유 설명하기 |
| 7. 개발 방식 | [개발과 검증](DEVELOPMENT_AND_INTERVIEW.md) | 요구사항·수정·검사·실측 근거가 연결된 작업 기록 한 개 쓰기 |
| 8. 설명과 재개 | 같은 문서의 면접 질문, [노트북 이전](../migration/README.md) | 3분 프로젝트 설명과 장치 없는 새 환경 확인 |

각 단계는 소요 시간보다 결과물을 기준으로 끝낸다. 이해가 안 되는 함수는 입력·출력·상태 변경을 적은 뒤 작은 합성 입력으로 확인한다. 큰 실행기부터 전부 해석하려고 시작하지 않는다.

## 학습 노트 틀

```text
질문: 이 함수가 해결하는 문제가 무엇인가?
파일/함수:
입력: 단위, 좌표계, 생성 시각, 출처
출력: 허가/거부/조향/구동 중 무엇인가?
상태: 다음 호출에도 남는 값은 무엇인가?
정상 예: 어떤 입력에서 진행하는가?
실패 예: 어떤 입력에서 멈추며 어떻게 회복하는가?
검증: 코드 이해 / 합성 검사 / 저장 자료 / 장치 / 실제 주행 중 무엇인가?
내 말로 설명:
아직 모르는 점:
```

GitHub에는 선별 코드와 설명이 있고, USB에는 비공개 원시 자료와 운용 의존성을 별도로 보존한다. USB가 없어도 첫 실패의 합성 재현과 호스트 조향 빌드부터 공부할 수 있다. 차량 제어 진입점은 학습 실습 명령에 포함하지 않았다.
