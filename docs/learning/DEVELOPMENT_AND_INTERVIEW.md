# 개발 과정을 이해하고 설명하기

## 이 프로젝트에서 배울 개발 순서

1. **요구를 관측 가능한 동작으로 바꾼다.** 예를 들어 “신호에서 잘 출발” 대신 “대상 light_1의 새로운 초록 입력 뒤 어떤 미션 상태가 어떤 조건에서 해제되는가”를 적는다.
2. **기존에 성공한 경로를 찾는다.** HYPER 모델·경로 재사용과 차량별 보정·제어 통합을 구분하고, 이미 실측한 부호·물리 한계를 다시 추측하지 않는다.
3. **문제가 있는 가장 작은 경계를 재현한다.** 신호 모델, 카메라 수신, 상태 머신, 시리얼, 물리 구동을 한꺼번에 바꾸면 원인을 구분하기 어렵다.
4. **변경과 관련된 검사부터 한다.** 통과 수만 늘리기보다 실제 실패 입력과 장시간 상태 전이, 복구 가능성을 포함한다.
5. **통합과 물리 검증의 차이를 남긴다.** 모의 경로가 계산된 것, 보드 출력이 전송된 것, 실제 차가 경로를 완주한 것은 다른 결과다.
6. **실행 가능한 소스와 근거를 함께 동결한다.** 명령·입력 종류·시각·해시·종료코드·미검증 범위를 기록한다. 실패 로그도 다음 실험의 입력이다.

당시 역할과 기록 절차는 원본 USB의 `docs/handoff/AI_WORKFLOW.md`에 남아 있다. 코드는 Codex/Claude 등 도구 지원을 받아 구현·검사했으므로 이를 전부 혼자 직접 작성한 코드라고 소개하지 않는다. 사용자 본인의 하드웨어 연결·현장 판단·시험 수행·요구사항 결정과 이해한 기술 내용을 구체적으로 설명한다. 팀 내 개인별 기여 비율은 기록만으로 확정하지 않는다.

## 결과를 설명하는 예시

> 1/5 스케일 자율주행 대회 차량에서 RTK 위치 기반 경로 추종, 조향 보정, Arduino 제어와 신호·미션 실행을 통합했습니다. HYPER의 기존 모델과 경로를 활용했습니다. 예선을 통과했고 본선에서 경사로와 경로 추종은 수행했지만 첫 신호등에서 재출발하지 못했습니다. 종료 후 로그를 분석해 신호 대기에서 위치 복구 잠금으로 상태가 바뀐 것을 확인했고, 그 잠금이 초록 입력보다 우선해 재개를 막는 경로를 합성 재현했습니다. 다만 당시 잠금 기준값이 충분히 기록되지 않아 최초 원인을 완전히 입증했다고 말하지는 않습니다.

이 문장을 외우기보다 코드·근거를 보여 주며 각 문장을 설명할 수 있어야 한다. “완주”, “모든 신호 검증”, “새 모델 학습 완료”, “실차 주차 성공”은 확인된 성과가 아니다.

| 이야기할 주제 | 준비할 근거 | 예상 후속 질문 |
|---|---|---|
| 경로 추종 | 직접 기록 경로 약111.8m, 기록 경로/GNSS 기준 횡오차 | 실측 지상 기준 오차인가? 속도·lookahead·heading은? |
| 조향 통합 | 차량별 ADC·각도·부호·좌우 한계 | 왜 원하는 조향각을 그대로 출력하면 안 되는가? |
| 신호 인식 | light_1 저장 사진의 기존 모델 평가 | 다른 신호/조명에도 일반화됐는가? 새로 학습했는가? |
| 통신 문제 해결 | 초기 역행·부분 프레임 재현과 수정 기록 | 바이트 스트림이 메시지 경계와 왜 다른가? |
| 첫 신호 실패 | 실제 이벤트 시간표와 합성 잠금 재현 | 관측한 사실과 추정한 원인을 어떻게 구분했는가? |
| 협업과 도구 | 요구·담당·검사·동결·로그 | AI가 작성한 결과를 어떤 기준으로 검토했는가? |

## 회고에서 피하지 말아야 할 점

준비 단계의 READY와 검사 개수만으로 완주 가능성을 자신 있게 말한 것은 근거가 부족했다. 최종 미션 상태에서 정지 이유가 바뀌는 과정과 자동 재개 가능성을 더 직접 확인했어야 했다. 모델 평가가 성공해도 상위 복구 잠금 때문에 결과가 사용되지 않을 수 있다는 것이 실제 사례다.

다음 개발의 후보는 정지 원인의 최초 발생값·해제 조건을 기록하고, 실제 수신 시계와 미션 전이를 연결해 재생하는 것이다. 이는 앞으로 할 일이며 이미 수정·검증한 성과로 쓰지 않는다. 개선안은 실제 위험 조건을 지우는 것보다 잘못 걸린 잠금과 회복 가능한 상태를 구분하는 데 초점을 둔다.

## 내 기여를 채우는 질문

- 직접 연결·측정·시행한 하드웨어 작업은 무엇인가?
- 어떤 현장 관측 때문에 요구를 바꿨고 그때 놓친 영향은 무엇인가?
- 지금 아무 도움 없이 설명할 수 있는 함수 세 개는 무엇인가?
- 코드 변경 하나에 대해 입력·출력·검사·실차 적용 여부를 설명할 수 있는가?
- 다시 시작한다면 첫 일주일에 무엇을 검증할 것인가?

개인 답변은 학습 후 본인의 경험으로 채운다. 모르는 부분을 공부 계획으로 분리하는 것이 허위 성과를 더하는 것보다 면접에서도 설명하기 쉽다.
